# 更新板与主动版本通知

版本0.2.2起实现新用户欢迎、按需指南、老用户更新通知三条独立流程。

## 用户体验

- 新邀请用户完成扫码、首次发可信消息后，自动收到一次使用指南。沿用原有欢迎队列，不因改版给所有用户重发初始化。
- 用户平时可以说「使用指南」查看说明，说「最近更新了什么」「更新公告」「有什么新功能」查看最新更新。
- 最新与历史版本在公共更新板`/guide?view=updates#updates`展示；原`/guide#updates`保留预览与入口。不含私人数据和日程令牌，可分享。
- 每次发布新版本，向当时已绑定且不处于首次欢迎流程的用户安排一次简短微信公告，正文包含新功能要点和该版本更新板链接。后加入用户不会收到历史版本广播。
- 表情开关与版本公告独立。「关闭表情包」不会停止功能更新通知。

## 如何发布下一次更新

修改`web/releases.json`，在最前面加入新版本号、日期、标题、摘要、功能点、体验示例和备注；同步更新使用指南中的操作说明。版本使用递增的三段数字，目录要求去重并按版本从新到旧排列。已发版本的内容不可原地覆盖，否则登记失败；修改已发布说明必须发一个新版本。

部署并通过小满原有检查后，后端每30秒检查最新目录：不存在的版本会在单一数据库事务中记录内容快照并为当前收件人入队；同版本重启、重复部署、重复检查均不再入队。新发布事务与发布记录、收件人快照一起提交，不会因中途失败永久漏掉一半用户。正常运行也可读取新目录文件，不需要给每位用户执行发送命令。

`CLAWBOT_ENABLED=true`时更新通知缺省开启；`CLAWBOT_ANNOUNCEMENTS_ENABLED=false`可暂停登记、领取及开始发送。此开关关闭后再恢复，不会重发已受理或结果不确定的通知。

## 实现边界

新增`clawbot_releases`与`clawbot_announcements`两张表，不复用Task、Reminder或欢迎记录，不重建旧任务。每版本每owner有唯一约束，按真实账号和发送者绑定隔离。新用户欢迎为waiting、pending、claimed或sending时不再叠加更新通知。

Node使用原生`sendText`适配器与独立`release-announcements`任务，每5秒通过内部鉴权接口领取：`/api/internal/clawbot/announcements/claim`、`/{id}/start`、`/{id}/result`。开始前再次核对绑定、总开关、7天时效和45秒领取凭据。领取超时且尚未发送可以恢复；进入sending后超过120秒记为unknown，重启、超时或ACK丢失不自动重发。已撤销用户的未开始通知会阻断。

内部`GET /api/internal/clawbot/announcements/status`返回版本与聚合状态、worker心跳，不返回微信ID、消息正文或令牌。accepted表示渠道受理；不等于手机已读或必然送达。失败与不确定结果单独统计，不能把已入队人数当作送达人数。

没有新增公网路径、公开发布接口或浏览器管理权限，不需要修改共享Nginx。公共更新板与微信公告使用同一个严格校验的目录，页面对文字和复制属性进行HTML转义，继续使用内联内容哈希CSP、no-store及no-referrer，不加载第三方脚本或统计。

## 验证

Python覆盖版本去重、后加入用户不补历史、首次欢迎不叠加、内容快照、撤销前后检查、功能暂停、到期、旧领取凭据、未知结果不重发、空平台回执、手动入口、资料收集和公网隔离；Node用假适配器验证公告独立队列、精确身份、单次发送、ACK丢失及异常行为。实际微信受理情况需上线后按聚合状态核验。
