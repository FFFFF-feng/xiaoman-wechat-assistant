# 小满上下文与陪伴交互改进规划

日期：2026-10-19。当前优先修复追问后的短回答和提醒后的任务指代，再完善名字记忆、自然表达、跟进策略和外部表情。本文的拟议行为不代表已上线。

## 已确认的问题

1. 原时间补全只拼接最后一条用户消息，连续回答“明天”“下午三点”会丢失最初事项；相对日期跨午夜还可能重新解释。
2. 主动提醒走独立投递队列，聊天历史里没有“刚提醒的任务”这个事实。模型即使看到“完成了”，也不知道具体对应哪条任务。
3. 到期通知由代码固定拼接“小满提醒、计划时间、操作说明”，单改聊天提示词不能改变它。
4. 现有15分钟任务引用只用于刚创建或改期的任务，不能当作用户长期偏好或永久名字记忆。

## 分阶段开发

| 阶段 | 工作 | 用户可感知的验收例子 | 进度 |
| --- | --- | --- | --- |
| 1. 接上上下文 | 持久保存待补全事项、日期、时间和改期对象；记录实际提醒对应的任务；检查否定、过期、多人和重复消息 | “提醒我写Java作业”→“明天”→“下午三点”，只创建一条正确任务；提醒后“完成了完成了，你别催了”能勾掉对应任务 | 本地完成，已发布GitHub预览，未部署 |
| 2. 记住名字和相处偏好 | 按用户保存助理名字、称呼和温和/俏皮风格，显式修改与重置；聊天、资料回应、欢迎和提醒读取当前设置 | “以后你叫团子”→隔天/服务重启后问“你叫什么”仍回答团子；不会改变其他人的名字 | 本地完成，未部署 |
| 3. 调整语言 | 共用表达规则与语气偏好；普通聊天、追问、任务回执、提醒分别处理；从真实任务状态生成短回应 | 用户明确要求后使用“大懒虫”等称呼；完成后简短回应，避免再重复完整时间和操作教程 | 到期提醒和完成回执已口语化，真实模型聊天效果待实测 |
| 4. 重要事项主动跟进 | 将提前提醒、到点提醒、询问完成分成独立阶段；持久保存下一次跟进时间、暂停和结束状态 | 建议重要事项提前20分钟、普通事项提前10分钟、低优先级到点提醒；提前阶段问准备好没，到点后按设定间隔询问完成情况 | 待开发，先给本地样例再上线 |
| 5. 扩充表情 | 下载许可明确的可爱素材，保存来源、版本、许可和校验值；按开心、收到、撒娇、鼓励、安慰等场景选择，避免同图重复 | 继续默认开启、不增加每日次数限制；用户说关闭后停止；现有凤鸟与外部表情混合使用 | 已调研来源，尚未下载或接入 |
| 6. 整体验收与发布 | 模型接通后的合成对话检查、手机灰度验收、更新板和版本通知；仅部署本项目 | 同一组连续对话验证任务状态和语气；不影响其他运行项目 | 各阶段完成后安排 |

阶段4拟议的默认跟进间隔为10分钟，次数和时段由设置确定，避免一条事项每分钟连续催促。用户说“做完了”结束事项及后续跟进；只说“别催了”暂停该事项催促，不能擅自标为完成；“十分钟后再叫我”修改下一次跟进。未知发送结果仍不自动重发。医疗、会议、出行等事项采用适当语气，不机械套用“大懒虫”。这些策略尚未启用。

名字保存在本项目数据库，跨日、重启和发布保留，直到用户修改、重置或删除相关数据；微信里显示的联系人资料是另一层设置。聊天历史有长度上限，名字等明确偏好不应随历史截断一起丢失。

## 本轮第一阶段实现

- 新增`pending_task_dialogues`：每个owner一条待补全请求，15分钟有效；日期在请求时固定，避免跨午夜重新解释“明天”。支持日期、时刻、上午/下午分轮回答、简单确认词、确定时间的问句以及“算了不用了”撤回。已有任务的缺时间改期也可继续补齐。
- 新增`reminder_dialogue_focus`：开始投递时记录对应提醒和当时的入站消息编号，30分钟有效。只有平台明确受理、任务未完成且未改期、用户未切换话题，才能用短完成回答定位它。平台受理不等于用户已读。
- 多条近期有效提醒、发送结果不确定、过期、跨用户、任务被改期或切换话题时，询问具体任务，不猜测完成对象。
- “没完成”“快完成了”、带任务名的否定报告、引述、疑问和条件语句不会因命中“完成”关键词就勾掉任务。保持现有消息幂等和任务归属校验。
- 新表由现有`init_db()`/`create_all()`新增，未改变旧表结构或重建任务。本轮未连接服务器、未发送真实微信测试消息、未发布新版本通知。

当前还不是完整的开放式长期对话记忆：复杂改口（如“不是Java，是Python”）、多个并行待确认事项以及隔很久的模糊指代仍需后续完善。资料导入或其他操作切换上下文时，短回答会重新确认，不把资料正文当作执行指令。

## 第二阶段与基础表达改进

新增`assistant_preferences`表，每个绑定身份分别保存助理名字、用户称呼和聊天语气，不依赖历史消息长度，也不设置自动过期时间。现有数据库初始化时只新增表，不重建旧任务、清空偏好或覆盖个人设置。

| 用户说法 | 实际行为 |
| --- | --- |
| 以后你叫团子 / 不要叫小满了，叫团子 | 业务层保存当前用户的助理名字；查询名字直接读取数据库，模型不可凭空确认改名 |
| 以后叫我小王 / 不要叫我小王了，叫老王 | 保存对用户的称呼，不会把助理改名为小王或老王 |
| 以后说话俏皮一点 / 语气温柔一点 / 说话自然一点 | 保存俏皮、温和或自然语气，后续模型调用读取当前设置 |
| 我的聊天偏好 | 查看本人的设置，不返回其他人的信息 |
| 恢复默认名字 / 恢复默认称呼 / 恢复默认语气 | 仅重置指定项目，不覆盖另外两项设置 |
| 团子，打开我的日程 / 团子打开一下我的日程 | 自定义名字可用于日程入口；重试旧消息不会因后来改名而丢失日程链接 |

普通聊天、图片/文档/聊天记录整理、首次欢迎和待发送的到期提醒读取个人名字。图片表情本身仍使用现有素材，不会修改素材文件里的文字。模型仅接收本人的名字、称呼、语气三个有界字段；它们作为字面数据注入，不是可执行指令。引用、条件、否定、过长或带附加操作的名字请求不会更改偏好；“你叫团子吗”不会把名字改成“团子吗”。

到期提醒改为本地生成的简短口语，不再重复计划时间和日程操作教程；创建和改期回执仍确认真实安排时间。自然、温和和俏皮各有数条表达，按任务稳定选择，不新增模型调用。只有用户明确设置过，才使用“大懒虫”等昵称；就医、服药、重要出行等事项避免调侃。完成回执根据已成功写入的任务状态生成，俏皮语气例如“好，勾掉「写Java作业」啦，收工！”。

这些改进不等于已实现提前或反复催促，也未证明真实模型闲聊已经达到满意效果。下一步仍需做合成对话和手机检查，再实现分级跟进与停止规则。

第二阶段本地验收：Python全量301项、Node连接器81项通过，其中新增16项覆盖名字持久化、不同用户隔离、用户称呼与助理名字区分、单项重置、问句与资料引用不改名、消息重试、自定义名字打开日程、跨引擎恢复、模型输入隔离，以及最新名字和语气用于提醒与完成回执。指南页面包含新设置说明，沿用原安全响应头；没有调用真实模型或向真人发送测试消息。本阶段继续以源码预览发布，不部署服务器、不变更线上版本目录或广播公告。
