# 图片、文件与聊天记录整理

2026-10-13：已部署到独立Linux实例并启用。服务器181项Python、65项Node离线回归通过，服务、网页及内部鉴权检查通过；手机附件全链路待验收。详见[上线验收](媒体与消息合并上线验收_2026-10-13.md)。

手机首次验收发现图片被误报为附件格式不支持：腾讯插件2.4.10将实际JPEG等图片标为`image/*`，旧连接器未兼容。已补充通配图片标记的路由及真实文件读取回归，仍由后端按文件内容验证JPEG、PNG、WebP及大小限制；不放宽文件路径或其他格式限制。手机重新发送后的完整回复仍需验收。

用户已确认手机能够正常识别图片。图片回复进一步调整为小满的自然聊天语气：生活照简短接话，通知及聊天截图直说重点，有多项信息才列点；去除固定“图片识别结果”标题和每张图都追加的提醒说明。确实整理出日程安排时才提示尚未设置提醒，仍不执行图片里的指令。文件及文字聊天记录继续按资料整理；新版回复语气待手机体验。

## 使用

- 直接发送一张JPEG、PNG或WebP图片：识别画面和文字；聊天截图按记录整理。会标注模糊或缺失信息。
- 直接发送TXT、Markdown、CSV、JSON、聊天记录XML、PDF、DOCX、XLSX文件：提取正文、摘要与待办草稿。XLSX保留工作表和单元格位置，公式只读取已有缓存值并标注未重算。
- 整段文字：发送`总结聊天记录：`后附正文，可保留姓名、时间和顺序。
- 多次粘贴：先发`整理聊天记录`，复制聊天文字并分多条粘贴发送，最后发`整理完毕`。15分钟内，文字仅作为资料，不创建、取消或修改任务；发`取消整理`退出。也支持同一批文字里包含开始、正文和结束命令。
- 微信原生转发入口：用户已确认此ClawBot不出现在微信转发联系人列表，因此逐条转发、合并转发都无法选择它。这是消息到达前的入口限制，后端增加识别代码无法让联系人出现。[腾讯插件仓库同类问题#198](https://github.com/Tencent/openclaw-weixin/issues/198)目前仍开放；问题提交者的协议原因猜测不当作已确认根因。
- 原生微信合并转发卡片正文：固定的腾讯插件2.4.10没有提供记录正文结构；仅收到卡片占位时会解释限制。截图、导出文件和复制粘贴整理不等同于微信原生转发支持；不能发送原生合并卡片给任意联系人，也不会主动读取其他微信会话。

全部识别结果只生成阅读结果和草稿。需要提醒时，结束整理后另发明确的任务、日期和时间。资料里的“明天”等相对日期保留原文，不能按导入当天推算。不把资料原文加入日程指令的历史上下文。

聊天JSON格式：按`messages`数组顺序读取，缺失的发送者和时间显示未知，不推造身份。

```json
{"messages":[
  {"sender":"甲","time":"2026-10-13 10:00","content":"周五交初稿"},
  {"sender":"乙","time":"2026-10-13 10:05","content":"改到下周一，请先确认日期"}
]}
```

也支持直接发送上述数组。XML支持导出的`recordinfo/datalist/dataitem`及`appmsg/recorditem`内的CDATA，不读取XML实体或远程附件链接。嵌套记录及未取得正文的附件明确显示缺失，不能声称完整读取。

## 限制与保存

- 每次一份附件，最多10MB；正文最多24000字，聊天JSON/XML最多200条，文字收集最多200行，PDF最多40页，图像最多1600万像素。
- 不静默截断超限正文；提示拆分。旧版DOC/XLS需另存DOCX/XLSX，不支持可执行文件、宏文档、加密文档和视频。
- 扫描版PDF未做页图OCR：空白或无可提取文字的页会明确提示补发图片；照片和长截图过密可能影响准确率。
- 附件原始内容及图片会经现有百炼模型配置处理，产生模型调用费用。没有另建文件云盘或外部下载入口。[百炼视觉接口文档](https://www.alibabacloud.com/help/zh/model-studio/vision)。
- 连接器只读取官方宿主提供、身份和消息ID吻合的本地入站附件；限制目录、大小、符号链接，拒绝从聊天正文推断文件路径或下载URL。
- 后端只保留附件哈希标记、摘要和处理状态，不新增保存附件二进制；官方插件自己的入站文件仍按其存储策略管理。文字收集期间，原文保存在私有数据库的`clawbot_import_sessions`，完成或取消后删除收集行；原有消息去重记录仍保留收到的文字。15分钟过期在下一条用户消息时清理，不能宣称准点物理删除所有历史原文。
- 绑定按账号与发送者隔离。模型读取后再次检查授权；同一消息ID不重复识别，失败后不自动重试或创建任务。

## 配置与部署

```dotenv
CLAWBOT_MATERIALS_ENABLED=true
VISION_MODEL=qwen3.8-flash
```

复用`MODEL_ENABLED`、`MODEL_API_KEY`/百炼密钥和`MODEL_BASE_URL`。视觉模型必须支持图片输入；可通过`VISION_MODEL`独立选择。关闭`CLAWBOT_MATERIALS_ENABLED`停用资料整理，正在收集的用户下一条文字会被安全拦截并退出模式。

在服务器独立源码/虚拟环境中更新本次文件，安装`requirements.txt`新增的Pillow、pypdf、defusedxml。备份数据库及运行配置后，正常重启小满后端和微信网关；后端初始化只新增`clawbot_import_sessions`表，保留已有任务。连接器依赖的`materials.js`和更新后的`voice.js`必须一并部署。不能在本机再次启动同一份微信授权。

内部新增`POST /api/internal/clawbot/materials`，保留连接器鉴权且不加入公网网关白名单。不需要增加公网端口、改变售后服务号或重新扫码。

## 验收

离线测试使用隔离SQLite、假模型和合成附件：图片、中文编码、DOCX表格正文、XLSX公式缓存、文字/扫描PDF提示、JSON/XML记录顺序、实体拒绝、大小与格式边界、身份与去重、撤销授权、收集完成/取消/过期、后文撤销及任务零写入。另回归原文字、语音、日程和提醒测试。

真实模型另用合成英文图片、中文文本文件、带后文改口的JSON记录验证，三类均通过关键来源信息检查；未读真人聊天、未写任务、未调用微信投递。可在已配置模型的环境执行`python scripts/check-materials.py --live`复测；此命令显式启用本次模型调用，会产生费用，不修改持久配置。
