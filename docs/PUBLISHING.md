# 发布与安全检查

## 上传范围

上传源码、网页、脚本、测试、通用说明和空凭据模板。以下保留本机，不上传：

- `.env`、`.env.official.local` 和其他真实配置。
- 私钥、模型密钥、AppSecret、Token、AESKey、access_token、完整私人日程链接。
- 数据库、聊天/日程数据、日志、备份、ZIP、虚拟环境、截图和缓存。
- 含具体公司部署地址、账号标识和操作日志的历史交接文档。

`.gitignore` 只保护未跟踪文件，不能清除历史泄露。首次提交前检查清单和内容，不上传上级工作区的安装包、截图和内部资料。

## 提交前检查

在Git仓库暂存拟上传文件后运行：

```powershell
git diff --cached --stat
git ls-files
.\.venv\Scripts\python.exe .\scripts\check-publication.py --staged
```

检查拒绝敏感路径、非空示例凭据和常见秘密格式，并在本机比对现有私有配置中的较长凭据。只报告文件名和类别，不输出凭据。它不是完整安全审计，不能识别所有秘密或业务数据；仍需人工核对权属、上传范围和可见性。

首次建议私有仓库。公开须负责人确认，不自动添加开源许可证或默认公司代码可公开。

## 运行与隐私

- 私有配置不放issue、README、截图或发布包，接口地址与密钥提供方匹配。
- 管理员扫码不绕过；权限、窗口、模板/订阅授权须实测。
- `accepted`不当作`delivered`；体验者自行生成自己的日程链接，不转发令牌。
- 主应用有本地开发接口和宽松CORS，只本机监听，经受限网关/独立反向代理接入公网。
- 热点、临时域名、休眠影响联调，隧道不是生产稳定性保证。
- 当前单worker，停服务只操作核对过的小满实例。
- 收集、传输、保留和删除真实聊天/日程需按实际授权、平台要求及适用规则设计。

## 凭据已泄露时

先在平台撤销/更换，再更新私有配置并验证。删除文件或设为私有不能使旧凭据失效。历史重写、影响评估和通知需负责人确认，不擅自强推或删除其他人的工作。
