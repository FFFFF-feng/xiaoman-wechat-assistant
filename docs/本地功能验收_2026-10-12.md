本人手机已确认：聊天、查询待办、单击机器人日程链接并看到页面、接收到期提醒均成功。本地补测发现的两处降级误建任务问题已修复，修复已加载到运行中的 Python 后端。

可以进入公司独立部署准备。当前结论不等于已正式上线，也不保证任意自然语言、隔夜提醒或长期网络可用性。

## 本次修复

### 1. 否定提醒被误创建

复现：模型不可用时，发送“不要提醒我明天上午十点整理否定事项”，原规则因匹配“提醒＋时间”而创建任务。

修复：在规则解析和模型/规则归并前检查命令否定。匹配的否定请求不创建、不改期、不完成、不取消现有任务；若确实要取消已有任务，需要明确提交取消命令。保留模型安全的聊天或澄清回复，拒绝其错误的任务操作。

### 2. 带时刻的条件提醒被误建为定时任务

复现：模型不可用时，发送“如果明天下午三点下雨就提醒我整理条件事项”，原规则忽略“如果下雨”的前提，创建普通定时任务。

修复：识别提醒动作之前的“如果、假如、要是、一旦”等条件语义，提示当前不支持条件自动触发，不写任务。下一轮仅补“明天十点”也不能绕过这个限制。

### 对照与回归保护

- “明天十点提醒我不要忘记带钥匙”仍可创建。
- “明天十点提醒我不要取消预约”按提醒事项处理，不把内容里的“取消”执行为取消已有任务。
- “明天十点提醒我检查天气”仍是正常定时提醒。
- 明确的查询、取消、完成和改期命令保持原功能。
- 模拟模型返回错误的创建、改期、完成、取消动作，以及否定/条件请求后的时间补全，均不能导致任务写入。

实现位置：`app/parser.py`、`app/chat_service.py`；回归：`tests/test_reminder_intent_safety.py`。这是已覆盖表达的确定性保护，不是完整语义理解或所有复杂表达都正确的证明。

## 当前本机启动方式

双击桌面“小满接入测试”，或 `clawbot-local/Start-Clawbot.cmd`。已运行时脚本验证进程归属，不重复启动副本；微信网关启动窗口须保留。本次只重载 Python，没有重启微信网关或日程隧道。

| 组件 | 本机地址 | 用途 |
| --- | --- | --- |
| Python 小满 | `127.0.0.1:18083` | 聊天、任务、鉴权和持久提醒队列 |
| 日程专用代理 | `127.0.0.1:18084` | 只转发页面和日程 API |
| 微信 Gateway | `127.0.0.1:18793` | 消息入站、回复与提醒投递 |
| 临时 HTTPS 隧道 | 每次实际生成的域名 | 手机访问日程；不要硬编码旧地址 |

最终检查：Python `ok`、调度器运行、真实模型可用、提醒 worker 在线；临时隧道 `ready=true`、`phase=online`。这是检查时状态，不是持续可用性承诺。

没有开机自启；关机、休眠、断网时不能保证消息或提醒。日程授权 30 分钟有效，隧道重建会换域名；失败时重新发送“打开日程”，不要复制旧链接。

## 公司独立部署前仍需完成

1. 确认授权的服务器、独立部署目录、端口、域名和运维权限；不修改旧售后服务号回调或菜单。
2. 补齐服务器启动方案：Python 后端、Node/OpenClaw/微信插件及提醒 worker 都要长期运行；现有 Windows 双击脚本不能直接当作 Linux 部署方案。
3. MVP 保持单 Python 进程、单调度器及单投递 worker，不直接开启多 worker/多副本，避免未经验证的并发和重复提醒。
4. 固定 HTTPS 日程入口保持白名单、鉴权和日志脱敏；不公开整个 Python 应用或 Gateway。
5. 安全迁移身份绑定、凭据和任务数据；完成备份、恢复、版本回滚、服务自启动和服务器重启演练。
6. 在服务器环境重新验收手机聊天、单击日程、真实提醒和用户隔离，再测试隔夜、长时间未互动、断网恢复与异常通知。

本轮实际后端聊天一次约 4.1 秒；隔离真实模型用例仍出现约 20 秒的单次处理，多轮用例耗时是累计值。均为小样本，不是微信全程延迟、压力测试或 SLA。

未完成：条件自动触发、循环提醒、多任务拆解、多人正式试用、群聊、媒体和合并转发聊天记录；不能作为上线能力对外承诺。
