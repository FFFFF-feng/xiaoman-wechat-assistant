# 小满名称、头像与微信资料边界

更新：2026-10-13，依据本机官方微信插件2.4.10，以及本轮核对的腾讯[官方协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)、[API实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/api.ts)和[类型定义](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/types.ts)。

## 扫码后自动设置公司头像与名称

结论：**当前接入路线未实现，也没有找到受支持的官方公开设置接口，不能承诺扫码后自动修改微信联系人资料。** 公布的接口覆盖扫码、收发消息、媒体上传、输入状态和客户端生命周期，不包含联系人资料设置；`bot_agent`仅用于日志归因。官方协议也说明客户端实现并非完整服务端契约，因此这是当前公开能力边界，不表示微信未来永远不能支持。

`IDENTITY.md`、网页Logo、欢迎消息或图片消息都不是微信联系人头像，不将其作为这个需求的替代验收。本轮没有更改公司服务器、已有公众号或售后系统。

如果统一微信联系人品牌是上线硬性要求，需要先获得微信侧正式支持的资料设置能力，或另行决定可控制账号品牌的接入渠道。没有确认前，不逆向私有接口、不尝试未公开的改名服务、不擅自换号或修改售后服务号配置。

**后续调研（2026-10-13）**：已查证到官方可行解法——**微信客服（企业微信客服）**的 `kf/account/add`、`kf/account/update` 接口可以用代码设置客服账号的**名称和头像**，`kf/add_contact_way` 生成添加/邀请入口。这是目前唯一能用官方接口同时控制"名称＋头像"的微信内入口。方案对比、改造成本与落地顺序见 [微信联系人头像/名称自动初始化：能力边界与可行方案](BRANDING_解决方案调研.md)。文中同时记录了本机插件 2.4.10 只有 7 个后端接口、协议不含昵称头像字段的实测证据。

## 项目身份与平台身份

| 位置 | 当前能力 |
| --- | --- |
| 小满聊天人设/业务回复 | 由Python小满负责，不使用OpenClaw默认人设回退 |
| 接入页与日程页 | 项目控制的网页，可以统一“小满”和项目图标 |
| OpenClaw本地Agent身份 | 新部署初始化为“小满”、猫爪图标和IDENTITY.md，仅本地后台元数据 |
| 手机微信中的ClawBot名称/头像 | 当前官方插件公开接口没有自动设置该资料的入口；不当作已实现 |

`scripts/setup-clawbot.py init`会生成本地 `workspace/IDENTITY.md`、`avatar.svg` 和Agent identity；**不会修改用户微信上的联系人头像或名称**。微信协议的 `bot_agent` 是日志/监控标识，不是微信昵称；不能通过修改它实现联系人改名。

用户若在自己的微信客户端有资料/备注编辑入口，可按客户端实际界面手动调整；当前不保证各版本都具有同一设置入口，也不声称能统一修改所有用户的联系人资料。不要将二维码、绑定Token或私有接口交给不明改名工具。

已有独立安装可运行`setup-clawbot.py features --root 你的绝对运行目录`，初始化本地小满身份并私密备份原配置，保留全部绑定和密钥。该命令不改微信联系人。发“小满资料”可以查看固定品牌说明，防止大模型误称已经改了微信头像；语音启用见[语音说明](VOICE.md)。

下一步候选开发：接入后显示明确的品牌说明与功能指引；首次有效入站后的欢迎语；接入自测状态与用户确认。欢迎语必须等待有效绑定和官方上下文，不能在扫码成功后盲目主动发送并宣称已送达。平台若后续提供正式资料接口，再单独实现和实机验收。
