# 连续消息合并与简短日程确认

## 当前状态

2026-10-13：已部署到独立Linux实例，线上已显式启用连续文字合并及简短确认文案。全新配置仍默认关闭，需显式启用；手机连发消息全链路验收待完成，详见[上线验收](媒体与消息合并上线验收_2026-10-13.md)。

## 处理规则

- 同一微信账号、同一私聊用户的连续文字按顺序合并，停顿4秒后统一处理和回复。
- 持续输入最多等待30秒；单批最多40条、8000字符。触及上限会分批，不保证任意长输入只回复一次。
- 新文字先写入私有持久队列，立即释放官方插件的串行收消息流程；不是在原同步回调中睡眠等待。
- 同一用户一次只处理一批，处理期间新收到的文字进入下一批；不同用户最多4批并行。
- 任务创建、查询与日程链接仍走原Python后端，使用原绑定身份，不重新扫码或更换任务归属。
- 批次消息ID由真实来源消息ID有序哈希派生，来源ID持续去重；不根据内容生成用户身份。
- 多个提醒要求或时间改口先统一确认，不擅自执行第一条。后文否定或撤回提醒时不创建。
- 原生已经转写成文字的语音可参与合并。需要百炼识别的WAV仍单独处理；若前面的文字尚未整理完，提示等待文字回复后重新发语音，避免乱序执行。
- `/echo`等腾讯插件原生命令绕过此队列，仍由官方插件处理。

合并按到达本机的时间判断，而不是手机发送时间。网络延迟、停顿超过4秒、超过容量或模型处理开始后的新消息，可能进入不同批次。当前不是完整的多任务批量执行引擎。

## 日程确认

创建示例：`记下啦，明天 10:00提醒你写周报。`

改期示例：`好，「写周报」改到后天 11:00。`

不再要求普通用户保持电脑、网关运行。主动提醒开关关闭时，仍简短说明`自动提醒暂不可用。`，不隐瞒提醒未启用。平台受理也不代表手机已经送达。

## 启用与关闭

以下是运维操作示例；本次已在服务器启用。后续变更先在隔离实例验收，不能让本机和公司服务器同时使用同一微信授权。

运行要求：Node `24.21.0`、OpenClaw `2026.10.1`、腾讯插件 `2.4.10`，使用Node内置`node:sqlite`，无额外npm依赖。

启用（`--root`替换为实际私有运行目录，不是源码目录）：

```bash
.venv/bin/python scripts/setup-clawbot.py text-batching --root /srv/xiaoman/runtime
```

此命令只在已归属实例中增加插件配置`mergeTextMessages: true`，先私密备份配置，不改变密钥、绑定、头像，不启动或重启服务。更新源码和配置后，需在确认可以短暂中断时正常重启小满后端与微信网关才生效；不要热重载、多网关并跑，也不需要重启整机或改其他业务。

关闭前先停止新输入、等待队列清空及正在处理的批次结束，再执行：

```bash
.venv/bin/python scripts/setup-clawbot.py text-batching --root /srv/xiaoman/runtime --disable-text-batching
```

正常重启网关后恢复逐条处理。关闭功能不会删除队列；仍有待处理文字时关闭，会将其留在队列中，重新启用后才继续。

## 持久化、失败与备份

私有文件：`state/xiaoman/text-batches.sqlite`，与`bridge.key`同目录。包含用户身份及聊天原文，不得上传GitHub、发送给体验者或写入公开日志。目录应为700、数据库600，Windows使用仅部署用户可访问的ACL。

尚未开始处理的文字可在重启后恢复。已冻结开始处理、发送中或超时结果不确定的批次不会自动重做任务或重复发送；重启后标记`unknown`。用户应先查询待办确认是否已执行，再明确重发新的请求。此策略避免重复任务，但不能保证崩溃窗口内的每条消息必达。

不得用删除队列文件、清理消息ID或自动重新扫码作为“修复”，否则会丢失待处理消息和去重记录。撤销用户时，待处理批次在执行前及发送前重新检查绑定，不向撤销成员发送结果。

备份原私有数据库、绑定、配置与凭据时也要包含此文件。安全备份方法是停止本实例输入、完成处理后正常停止网关，再复制队列；不要复制正在写入的SQLite文件。备份仍按私有凭据级别保存。

## 验收

离线测试覆盖20条顺序入站→一次处理/回复、停顿与最大等待、容量、跨用户及跨账号隔离、来源ID去重、重启、不确定发送不重试、撤销检查、文字/语音顺序和后文否定/条件/时间改口。

未来真人验收：

1. 连续发送`提醒我`、`明天`、`上午十点`、`写周报`，只创建一个本人任务，收到一条简短确认。
2. 一件普通聊天分成20条，每条间隔小于4秒，停顿后收到一次统一回复。
3. 连发`明天十点提醒我写周报`、`算了，不要提醒我`，不创建任务。
4. 两位同时连发，回复和日程均不串人。
5. 重启恢复和未知发送场景先查待办，不能以自动补发来验收“成功”。
