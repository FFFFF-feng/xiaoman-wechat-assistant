## P0：正式号真实闭环

| 工作包 | 具体任务 | 验收条件 |
| --- | --- | --- |
| 账号就绪 | 区分提额、注册、认证和接口权限，记录可用渠道 | 状态明确，不以有密钥代替权限 |
| 新号隔离 | 独立私有配置、数据库和实例，保留旧号 | 新号无法读旧号日程，旧任务不误发 |
| 低延迟回复 | 记录解析/模型/数据库/发送耗时，设置整体预算 | 慢模型有可预测降级，不假称操作成功 |
| 真实提醒 | 手机聊天、创建、提醒、日程、完成/改期/取消 | 真实收到，失败可核查 |
| 安全检查 | 脱敏、路由白名单、访问令牌、验签与排重 | 调试不公开，重试不重复创建/发送 |

先测耗时，再区分无需模型的指令与复杂请求。被动回复需更短的整体预算；异步模式只在发送权限可用后选择，不能靠模式切换绕权限。

## P1：可靠性与跨窗口通知

### 可靠性

1. 锁定依赖、处理TestClient弃用警告，验证Python 3.12/3.13。
2. 持久调度：任务领取、幂等键、恢复和过期策略；单实例先通过再考虑多实例。
3. 完善状态机：明确失败与结果不明分开，不盲目重试，有回执才能认定对应送达。
4. 运维：日志脱敏/轮转、存活与积压指标、异常告警、备份恢复演练。
5. 数据治理：保留期限、导出/删除、最小权限、审计记录。
6. 自动回归：提交时执行离线测试与发布检查；真实消息测试另外授权，控制成本与接收人。

### 跨窗口通知

- 核对真实模板/订阅权限、业务类目与字段，不承诺无限提醒。
- 建立用户同意入口，以及拒绝、撤回、取消关注后的停止发送流程。
- 没有真实同意回调时不生成虚假额度。
- 区分传统模板、旧一次性订阅接口和订阅通知`bizsend`，不混用模板。
- 真实窗口外送达单独验收；两分钟提醒或mock不足以证明。

## P2：可控的智能增强

| 方向 | 最小可行版本 | 边界 |
| --- | --- | --- |
| 结构化偏好 | 用户保存一项偏好，展示来源，可编辑/删除 | 不持久化情绪/身份等隐式猜测 |
| 任务拆解 | 为一个大任务建议少量步骤，确认后建立 | 不自动执行或批量骚扰 |
| 安静时段/合并 | 用户设置频率偏好，有解释和开关 | 不突破窗口、额度或授权 |
| 语音转任务 | 转写、回显、时间确认，可更正 | 不默认存音频，不直接执行不确定转写 |
| 冲突提示 | 检测明确冲突/临近截止并说明原因 | 不自动移动/删除，不假装接入外部日历 |
| 企业知识库 | 少量授权资料、出处、按权限检索 | 防止资料越权和提示注入，不擅自上传资料 |
| 多渠道 | 复用业务层，逐渠道定义能力限制 | 不擅自合并账号身份，不绕平台规则 |

优先小范围探索“提醒状态解释”和“可纠正偏好”；其他方向依据真实需求决定，不全部并行开发。

## 评测方法

先建立脱敏样例集，再订目标。以下是建议观测项，不是已经达标的数值：

- 日程：意图、标题、日期时间、缺失信息追问；单独统计高风险误操作。
- 对话：模型成功率、降级率、延迟P50/P95、有效交互成本。
- 提醒：资格、API接受、可关联送达、超窗口阻止、失败、重复与漏发分别统计。
- 隐私：拒绝跨用户/跨账号/过期令牌，撤回后不继续发送。
- 稳定性：注入断网、超时、进程中断和重启，结果不明不冒进重试。

每次只改一个主要因素，用同一批样例比较，记录环境、模型ID和依赖版本，不记录密钥或私人聊天。

## 协作方法

需求：场景 → 输入 → 预期动作 → 失败说明 → 验收样例。

开发：小改动 → 自动测试 → 本地体验 → 经确认的真实联调 → 回滚方案。

扫码、资质、认证付款、权限、域名和服务器窗口需要负责人配合，不能由编码替代。审核期间可准备样例集、慢模型测试、状态解释和文档，不必修改旧号或公司服务器。
