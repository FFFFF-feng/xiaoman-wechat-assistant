# 小满日常表情

2026-10-17 已按用户授权部署到现有Linux小满实例，默认开启，无次数与冷却限制。服务器隔离回归Python242项、Node78项通过，提醒worker在线；未向真实用户发送测试图片，手机效果与送达待验收，详见[上线记录](日程入口与表情上线验收_2026-10-17.md)。本组使用上一轮推荐的D版凤鸟，保留红色、浅色眉羽与凤冠；不覆盖当前引导暂用的第一轮A版头像。

## 素材与实际发送形式

`assets/stickers/phoenix-d/` 包含14张1254×1254透明RGBA PNG：早呀、收到、加油、歇一下、谢谢你、晚安，以及新增哈哈哈、抱抱、在呢、委屈、好哒、辛苦啦、等等我、出发。由内置image_gen根据现有角色参考分别生成，文字及透明通道已检查。原图完整保留，不临时生成、不按次调用模型，也不读取用户提供的文件路径。`manifest.json`固定ID、文件名、文案与SHA-256。

本轮通过腾讯插件的图片通道发送静态PNG，**不是微信原生表情商店上架、动态图或emoji消息类型**。最终在手机中的显示、透明背景及收藏体验仍需真实设备验收。

## 用户如何使用

按2026-10-17用户要求，ClawBot启用时`CLAWBOT_STICKERS_ENABLED`缺省为true；显式false仍可由管理员暂停。部署素材/代码并重启本项目后端与微信网关后，已有及新绑定用户自动开启，无需手动订阅。若运行配置已经写入false，正式上线时需改为true。现有服务器已启用，其他运行环境值、绑定和网关配置保留。公告通过公共使用指南发布，没有批量发送微信公告。

| 用户发送 | 实际行为 |
| --- | --- |
| `表情包` / `表情设置` | 查看用法及本人两个订阅开关 |
| `给我收到表情包` | 立即安排一张指定表情；也支持其他5张的名称 |
| `发个表情包` | 安排一张“收到”；支持“发个早安表情包”等别名 |
| `开启聊天表情` | 普通闲聊、情绪、打招呼、道谢、晚安等场景配图；按用户状态选图，同类轮换，正常文字回复保留 |
| `关闭聊天表情` | 停止聊天配图，取消尚未开始的聊天表情 |
| `开启日常表情` | 从次日起北京时间9:00—9:15窗口尝试发送一张“早呀” |
| `关闭日常表情` | 取消每日问候及尚未开始的每日表情 |
| `关闭表情包` / `不要再发表情` | 同时关闭两种自动发送，并取消本人所有尚未开始的表情；主动索取仍可使用 |
| `开启表情包` / `恢复表情包` / `可以发表情了` | 同时恢复聊天配图与每日问候；重复开启不会重置日期 |

用户两个开关默认开启、按真实绑定owner隔离。调度检查会在任何时段为缺少偏好的绑定初始化开关，收到新消息时也会初始化；只创建缺失记录，绝不覆盖已保存的关闭选择。聊天配图及主动索取不设每日次数、短时次数或冷却间隔，也不再附加“近24小时活跃”条件。

每日问候是北京时间每天9点的单次事件：在9:00—9:15窗口尝试发送一张“早呀”，首次自动开启或重新开启的当日不补发，从次日开始；错过不补发、不在夜间补问候。相同日期和同一入站消息仍去重，避免重启或回调重复发送。这是定时事件与防重语义，不是表情次数限流。

小满不额外限制表情发送次数，**不代表微信平台无限制或保证送达**。平台仍可能因为自身规则、上下文或网络拒绝，accepted也仅表示受理。原有桥接接口防护、资源校验、消息时效和异常不重发机制保留。关闭指令在部署总开关暂时关闭时仍持久保存，避免日后恢复功能又自动订阅；已进入原生发送的图片无法追回。

## 链路与边界

1. 现有入站Bearer鉴权及允许列表确认发送者；正文不能指定owner或收件人。消息级去重沿用既有`clawbot_messages`。
2. 命令/聊天或独立30秒调度检查写入`clawbot_sticker_deliveries`，不创建Task或Reminder；`(owner_id,event_key)`唯一。偏好独立保存到`clawbot_sticker_preferences`。只新增两张表，不重建旧数据。
3. 网关`deliver-stickers`任务每5秒使用内部`/api/internal/clawbot/stickers/claim`、`/{id}/start`、`/{id}/result`领取并回写。开始前再次检查绑定、开关、过期、素材与领取凭据。
4. Node端使用固定表情ID、受限目录、普通文件/非符号链接、PNG头、4MiB上限及SHA-256校验。API不接受媒体URL或本地路径。`sendMedia`的收件账号、用户、mediaUrl及mediaLocalRoots均由可信代码确定。
5. 使用OpenClaw宿主`loadAdapter('openclaw-weixin').sendMedia(...)`，账号、微信授权、CDN和回复上下文继续由腾讯插件管理。素材不开放新的公网路径，不更改Nginx，不启用Agent工具。

固定腾讯插件`2.4.10`的npm发布包已下载到忽略的`.cache`并核对registry提供的完整性摘要，仅阅读`channel.ts`及`send-media.ts`。其sendMedia接受本地文件，PNG进入图片上传分支。没有升级、安装或运行该发布包；当前接口的官方源码可参考[Tencent仓库](https://github.com/Tencent/openclaw-weixin/blob/main/src/channel.ts)。

## 失败与重放

发送前领取45秒失效可恢复，但旧凭据失效。进入sending后不会再回pending；超过120秒记为unknown，不因超时、重启、ACK丢失或平台异常自动重发。缺少sendMedia能力时不领取、不偷偷改成文字。没有平台消息ID不会记录accepted。发送结果接口重复ACK不重复发送。

导入聊天记录期间的文字仍交给原有收集逻辑，不把记录中的“开启日常表情”执行为指令；否定和带引号的命令不触发开关。功能总开关、素材缺失或校验失败时不谎称已经发出图片。既有提醒、欢迎队列及文字批处理保持独立。

默认开启改版连同自然日程入口的完整离线回归：本地与服务器均为Python242项、微信连接器Node78项通过，其中表情专项Python20项。六张素材均为1254×1254、带真实透明通道的PNG，每张小于4MiB，浏览器预览全部加载正常。下载包及完整生成提示词保存在忽略的`output/stickers-20261017/`，应用运行素材在上面的`assets`目录。

使用独立环境文件、内存SQLite和虚构Alice/Bob，禁用真实模型与微信发送。Python用例覆盖归属、默认开启、已有绑定初始化、退出不被覆盖、恢复、连续索取与聊天不限次数/间隔、上海时间日期、时段、去重、过期、旧凭据、撤销、发送不确定、资料收集与公网隔离；Node用例通过假适配器检查真实素材校验和sendMedia参数、失败与ACK丢失行为。尚未做真实微信图片发送验收。

用户已检阅并授权部署；发布前已备份，只更新和重启小满四个服务，另37个运行服务、共享Nginx和其他监听端口保持原状。手机图片发送与关闭/恢复仍待真人验收。未来若要更换凤鸟版本，生成独立素材目录并更新固定清单，不覆盖已经在途的素材。

## 第二轮表情扩展（0.2.2）

本轮新增8张，沿用D版原创角色，内置image_gen逐张生成，原始PNG及透明通道保留。参考[LINE FRIENDS官方角色介绍](https://linefriends.com/en/characters-list/ip-linefriends)的日常情绪覆盖与[卡娜赫拉官方表情组](https://store.line.me/stickershop/product/1000509)的性格反差，采用短文案、明显肢体动作和易读轮廓；不使用其他品牌角色图像。新增大笑、抱抱、倾听、委屈、肯定、慰劳、等待和出发场景。生成提示词和来源记录保存在本地output/stickers-expansion-prompts-20261017.json，应用素材纳入固定清单。

配图不再只匹配几个完整词：先按负面情绪、疲惫、打招呼、感谢、开心、出发等顺序匹配，普通闲聊也配图，同类候选避开上一张；每条普通聊天至多搭配一张，不设每日次数或冷却。急事、引用、较长信息、代码/步骤等信息型问题不添加无关反应。资料整理、日程和失败提示不走普通聊天配图分支。用户说“以后不要再给我发表情包了”也会持久关闭。

## 宿主隔离目录修复（0.2.3）

手机反馈图片缺失后，确认素材文件完整，队列已领取，但发送前定位失败。OpenClaw将插件捕获到隔离运行目录，基于import.meta.url向上推导仓库素材路径失效；普通Node直接导入测试未覆盖这一点。新增受信任部署配置`plugins.entries.xiaoman-bridge.config.stickerAssetsDir`，使用资产原目录的绝对路径。初始化脚本已写入此字段；已有实例升级时也必须配置，例如Linux部署为`/srv/xiaoman/app/assets/stickers/phoenix-d`。不从用户消息、模型回复或队列API接收素材路径。

固定ID、普通文件、非符号链接、绝对路径、PNG头、大小和SHA-256校验保留。素材预检失败会记录failed/asset_unavailable，而非反复领取到过期；未进入通道的失败不声称已发送。模型加入当前图片能力与凤鸟身份，不再说“只能发文字”，也不能把文字当作图片送达证明。

最新本地及服务器Python263项、Node81项通过，包含复制到隔离目录后使用显式素材路径的回归。另用服务器实际OpenClaw捕获器验证修复；对截图中的原请求唯一匹配后补发一张抱抱，真实图片通道返回消息标识，记为accepted。手机实际显示仍由用户确认。

## 外部3D表情与个人风格（0.2.4预览，2026-10-19）

本轮只做本地开发，未连接或部署服务器、未给真实用户发送测试消息、未广播公告。上文各次服务器验证是对应历史版本的记录，不代表本轮38张素材已经上线。

在原14张原创小凤鸟基础上，加入24张[Microsoft Fluent Emoji](https://github.com/microsoft/fluentui-emoji)原始PNG，覆盖笑脸、猫猫、狗狗、兔兔、熊猫、抱抱、鼓掌、点赞、挥手、犯困和热饮等场景，共38张。固定上游提交为`1ffb34c752ecf5d402f04cfb4b392c77f57c54bc`，选用的外部文件均为256×256 RGBA PNG，保留原字节，没有另行修改或生成。仍通过静态图片通道发送，手机缩放、透明背景和收藏体验待验收。

来源清单在`assets/stickers/fluent-source.json`，包含每张上游路径、Git blob SHA、用途和中文选择名称。下载工具`scripts/fetch-fluent-stickers.py`只从固定微软仓库与提交获取这份清单内的素材和许可，核验Git blob SHA后，用Pillow只读检查PNG格式、尺寸和RGBA通道；全部验证成功才写入素材目录。现有`manifest.json`另存SHA-256、上游链接、许可和许可文件位置。

按上游[MIT许可](https://github.com/microsoft/fluentui-emoji/blob/1ffb34c752ecf5d402f04cfb4b392c77f57c54bc/LICENSE)保留完整Microsoft版权及许可文本，随包存放在`assets/stickers/phoenix-d/licenses/fluent-emoji-LICENSE.txt`。原创凤鸟与上游素材的来源分别记录，不把第三方作品标为本项目原创。

### 使用与实际行为

| 说法 | 行为 |
| --- | --- |
| 只用小凤鸟表情 | 自动聊天配图和日常问候使用原创小凤鸟 |
| 只用3D表情 | 自动配图使用Fluent素材；早安使用挥手或热饮 |
| 混合表情 / 表情风格随机 | 恢复默认混合搭配，两组按场景选图 |
| 来张猫猫表情 / 给我3D抱抱表情包 | 明确索取指定外部图片；命名索取优先于自动风格 |
| 给我收到表情包 | 默认仍使用原“收到”；在只用3D风格时选择对应的肯定表情 |
| 换张表情 / 换一种表情 | 按当前风格换一张中性日常表情，尽量避开最近图片 |
| 表情设置 | 查看本人风格、聊天和日常开关及可索取名称 |

风格保存在新增独立表`clawbot_sticker_styles`，按owner隔离，无自动过期；跨数据库会话、服务重启保留，直到用户修改或删除数据。没有风格记录时为mixed。初始化只新增表，不修改旧表列、不覆盖旧开关。改变风格不会重新开启已关闭的聊天或日常表情；管理员暂停发送时仍能保存风格和退出选择。带引号、条件句、资料导入中的同名文字不会执行风格切换。

改变风格时取消本人尚未开始的自动图片、使已领取凭据失效；明确索取的手动图片保留，已经进入原生发送的图片无法追回。重复设置同一风格不取消当前队列。同一天已经创建过早安事件，切换风格后不再补发第二个。

聊天按安慰、难过、疲惫、早晚问候、感谢、开心、鼓励、等待、出发、亲近和普通闲聊选择固定候选，优先避开最近三张；候选不足时回退到尽量不重复上一张。负面情绪优先于“哈哈”等快乐词。信息问题、表情设置讨论、急事、医疗、丧事、引用和长文本不额外搭图。素材不可用时只在当前风格和对应场景中寻找有效候选；mixed可继续使用旧素材，fluent专用风格不会偷偷换成凤鸟。

成功创建、改期和完成任务也会搭配一张“收到”或庆祝图，共用聊天表情开关和消息去重。失败、待补时间、列表、日程链接、资料整理不会因任务关键词而发图；任务状态未成功变化时不庆祝。健康或急事内容不配娱乐表情。不新增模型调用，不增加每日次数、冷却或近24小时活跃限制。
