# 用户接入与统一入口规划

更新：2026-10-12。目标是一个统一入口，用户不需要安装源码、配置模型密钥或登录服务器。

## 当前能否分享给别人使用

可以分享 GitHub 仓库供查看源码和本地模拟体验；当前不能把本人 ClawBot 绑定二维码当作已经上线的公共加好友入口。

现有版本只验收了本人扫码登录，业务连接器需要匹配私有 `account_id + sender_id` 允许列表。未绑定用户被拒绝；本机启动和检查脚本还有“恰好一个绑定”的限制。核心后端已有按身份隔离任务与历史的设计及双用户模拟测试，但多人真实登录、统一注册页面和运营管理尚未完成。

仅将代码上传 GitHub 或搬到服务器，不会让其他微信用户自动获得访问权限。不要分发密钥、绑定文件、数据库、个人日程授权链接或整个本机运行目录。

## 统一入口采用什么方式

优先沿用当前插件路线，规划一个固定 HTTPS 的“小满接入页”：大家访问同一个网址，但每位用户分别使用自己的微信扫码并确认授权，随后在各自的 ClawBot 会话中使用小满。后端由公司统一托管，用户无需操作服务器。

腾讯插件说明支持一个 Gateway 同时运行多个微信账号，并要求按账号、渠道和对端隔离会话；每个账号需要分别登录。[腾讯插件官方说明](https://github.com/Tencent/openclaw-weixin/blob/main/README.zh_CN.md)

上述是据此制定的项目方案，不是现成的网页注册功能。官方多账号登录能力不等于一个永久微信好友二维码、任意转发二维码后即可获得权限，或项目已经支持公开多人使用。

如果要求的是“所有人关注同一个服务号/添加同一个公共联系人就能聊”，这是另一种渠道目标，需要单独核对平台能力与现有业务冲突；不能靠修改插件允许列表保证实现。

## 开发后普通用户怎么使用

以下为预期流程，当前尚未上线：

1. 打开统一接入网址，查看功能范围、隐私说明及服务限制。
2. 首轮试用输入邀请凭证，点击“连接微信”；页面只展示本次用户专属、短时有效的登录二维码。
3. 用本人微信扫一扫，在手机确认授权。二维码过期可重新申请，不复用他人的二维码。
4. 页面显示连接成功后，在自己的 ClawBot 会话发“你好，小满”。
5. 使用“明天十点提醒我提交周报”“查询待办”“打开日程”等指令；自己的日程链接只供本人使用。
6. 在接入页查看连接状态、撤销绑定、申请删除或导出自己的数据；这些管理功能需要开发。

同一接入页不代表共用聊天历史或任务列表，也不要求每位用户配置 IP 白名单、API 密钥或服务器权限。

## 计划开发项

| 工作项 | 具体改动 | 验收条件 |
| --- | --- | --- |
| 接入页面 | 固定网址、说明、邀请认证、扫码会话和连接状态 | 不开放 OpenClaw 原始管理界面，不回显凭据 |
| 登录会话管理 | 使用宿主/插件支持的登录流程，二维码短时有效，进度与请求者绑定 | 禁止会话抢占、二维码混用、跨用户查看和反复重放；不直接复刻私有协议 |
| 多人绑定 | 真实登录确认后原子登记可信账号/扫码者，保留旧绑定，支持撤销 | 新用户不覆盖本人，未授权用户不放行；撤销后不再处理消息或发送提醒 |
| 宿主账号与路由 | 加载各授权账号，配置会话隔离；去除本机启动脚本的单人假设 | 两个真实微信同时收发，彼此任务/历史/日程隔离 |
| 多人提醒 | 保留账号和收件人对应关系，按用户查询投递与连接状态 | 真实提醒只到本人，断连/取消/改期不误投或重复投递 |
| 配额与运营 | 每用户调用/提醒限制、成本上限、异常状态和管理员审计 | 滥用不会无限消耗模型额度，管理员页面有独立权限 |
| 隐私与数据管理 | 明示数据进入模型提供方、保存期限、导出/删除及授权撤回 | 有可执行的流程，不只写在说明中 |

首轮不开放任意公众匿名注册，先通过统一入口邀请少量真实用户。双用户隔离、撤销、超时、重启和成本限制验收后，才扩大规模。

## 推荐推进顺序

1. 完成公司单用户独立部署，固定日程 HTTPS；确认离开开发电脑后仍能聊天和提醒。
2. 在受控环境添加第二个真实微信账号，验证插件多账号登录、业务绑定和隔离，不用虚构 sender_id 或放开所有人代替。
3. 开发统一接入页和受控的扫码登录管理；保留确认、撤销、限流与审计。
4. 邀请少量用户按同一入口完成端到端验收，再决定公开范围。
